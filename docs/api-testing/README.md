# API Testing – Student Management System

## 1. Overview

This guide explains how to test the Student Management System REST API with **Postman** (manual requests) and **Newman** (automated collection execution).

The backend uses Node.js, Express.js, Mongoose, and MongoDB Atlas.

**Latest recorded Newman execution (20 November 2026):** **121 HTTP requests**, **210 assertions passed**, **0 failures**. Total duration: **34.1 seconds**; average response time: **74 ms**. These figures come from the shared Newman terminal output.

## 3. Manual Testing with Postman

1. Install project dependencies:

   ```bash
   npm install
   ```

2. Configure the MongoDB connection in `.env` using `.env.example` as a template. Use a disposable database for testing.
3. Start the backend:

   ```bash
   npm run serve
   ```

4. Import the collection into Postman:

   ```text
   collection/Student Management System API - Newman.postman_collection.json
   ```

5. Select the included Postman environment or configure:

   ```text
   base_url = http://localhost:3000
   ```

6. Execute requests in the required order, especially where later tests use SIDs generated by earlier requests.

**Note:** Student IDs are generated by the server on creation. Do not assume the SID sent in a POST request will be stored. Some requests create, update, and delete records; do not use important data.

## 4. Automated Testing with Newman

Newman runs the collection against a separate API server on port **3001** and a dedicated MongoDB Atlas test database named **`stu-management-test`**.

### 4.1 Configure the Test Environment

1. Copy `.env.test.example` to `.env.test`.
2. Set the test-only environment variables:

   ```env
   MONGODB_URI=your_test_database_connection_string
   TEST_DB_HOST=your_mongodb_hostname
   ALLOW_TEST_DB_RESET=false
   PORT=3001
   ```

3. Confirm the connection string targets `stu-management-test`.
4. Confirm `TEST_DB_HOST` matches the MongoDB hostname in the connection string.
5. Only after verifying the test database, change:

   ```env
   ALLOW_TEST_DB_RESET=true
   ```

**Warning:** The automated runner resets student records in the configured test database. Never point it at a development or production database. Do not commit `.env.test` or credentials.

### 4.2 Run the Tests

From the project root:

```bash
npm test
```

The runner checks the configuration, prepares test data, starts the test server, executes Newman, generates reports, and stops the test server.

## 6. Test Coverage

The automated collection contains **121 HTTP requests** covering:

- Student retrieval, creation, updates, deletion, and search.
- Required fields, email formats, name lengths, and course/subject validation.
- Search case sensitivity, whitespace, partial matching, and SID format checks.
- Server-generated SIDs and protection against SID modification.
- HTTP error handling and preservation of data after rejected updates.
- **API-117–API-122:** One-word first/last-name validation and regression checks.

**API-115** is a historical **manual MongoDB restoration verification**, documented in `test-cases.md`; it is **not** counted among the 121 Newman HTTP requests.

- Manual API port: **3000**; automated API port: **3001**.
- Use isolated, disposable data for both manual and automated tests.
- Never commit `.env`, `.env.test`, or MongoDB credentials.
